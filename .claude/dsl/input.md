# DSL reference: Input

The whole story of these verbs. The one-line index is `.claude/rules/dsl-reference.md`.

- `held(:left)` — 1 while down; `pressed(:start)` — 1 on the press edge only. Use with `if`.
- `held(:any)` / `pressed(:any)` — **any button at all**, which is how a game leaves an attract screen, a splash or a cut scene: `mode = :title if pressed(:any)`. `pressed(:any)` is true on a frame some button went down, the same edge each button has on its own — so A pressed while LEFT is still held counts, and a button held on and on is one press. It is one test against all ten buttons, cheaper than the ten `held` tests joined with `||` it replaces, and none can be left out. `:any` is not a button: a test's `hold(...)` and the command line's held keys refuse it, since holding "any" means nothing.
- `held(:left, player: 3)` / `pressed(:start, player: 2)` — **another player's controller**, from 1 to 16 (`IR::Buttons::MOST_PLAYERS`). `player: :any` is every connected player, so `pressed(:start, player: :any)` lets anybody leave a title. `:any` as the button works with it, `pressed(:any, player: 2)`. `if_held` and `if_pressed` take `player:` too. A number that is not a player (`0`, `17`, `:third`) is a friendly error at the line. Only a number written in the game: a player number worked out as the game runs is not taken yet, so a game for four writes the four, or a Ruby loop at build time (`places.each.with_index(1) { |x, p| x.increase!(1) if held(:right, player: p) }`, `places` a list of `var`s).
- **How many each console seats.** Game Boy Advance and Color: one controller, so `player: 2` and more are refused at the build in plain words, and `player: :any` reads that one. Super Nintendo: two (a Multitap is not read yet). Sega Genesis: one (the second pad is not read yet). A build that plays on a computer (C, a web page, Ruby): the desktop and browser builds read two players for now and refuse more naming the Ruby build; the Ruby build (`vblank run`) reads all sixteen. Sixteen is the computer's ceiling: it catches a typo, and the buttons of one pass stay one small list a network can carry, 32 bytes a pass. Each console's page says the same.
- `players: 4` on `VBlank.game` (or `VBlank.build`) — **how many players the game takes**: `4` is 1 to 4, `2..4` at least 2 and at most 4, and by console, `players: { snes: 1..2, computer: 1..8, else: 1 }`. A key is a console's name, `computer:` (any build that plays on a computer, whichever console it is made as) or `else:` (every build the rest do not name); a computer build reads `computer:`, then its console's, then `else:`. Then a line that reads a player past the most is a friendly error, and a console that cannot seat the most refuses the game at the build, even where no line names the last player yet (a game that reads `player: :any` would lose players quietly otherwise). Saying nothing is fine: the game reads whichever players its lines name, and each console refuses what it lacks. The fewest is kept for a joining screen; nothing reads it yet. Errors: a count that is not 1 to 16, a range backwards, a key that is no console, a console the game is not for.
- `players_connected` → a `Value`, **how many players are connected now**, at least 1. A player counts from the first time one of their buttons is down, and stays counted: letting go of every button is not unplugging. Ask it before waiting on a player, so a game never reads a missing player as idle: `draw_text "P3 PRESS START", 40, 80, :white if players_connected >= 3`. A console that reads one controller answers 1. The Super Nintendo's cartridge build does not make it yet and refuses it by name (it cannot yet tell whether the second controller is plugged in: wait for a button on it instead); a build of the same game for a computer answers it.
- **In a test or a tape**, another player's buttons have the player's number in front: `hold(:left, :p3_left)`, `:p2_start`, up to `:p16_a`, in `hold`, `input_each_frame`, a script and a tape. Holding `:p3_left` once makes three players connected from then on. **Where the buttons go**: the interpreter keeps the names; a computer's runtime is handed one number per connected player each pass, the first player's first, a bit a button (`IR::Buttons.masks`, kept from pass to pass by `IR::Buttons::PassButtons`) — the plain list a network will carry later. A console reads its own controller ports. A game that never names a player past the first builds the same bytes as before. A computer's window has keys for the first player only. Worked examples: `test/interpreter/vblank/builder/test_many_players_interpreter.rb` (four markers), `test/lowering/ruby/vblank/ir/backends/ruby/test_ruby_many_players.rb` (twelve players as Ruby), `test/all/vblank/builder/test_player_option.rb` (what each console refuses).
- Low-level: `if_held(:a) { }` / `if_pressed(:a) { }`. Buttons: `a b select start right left up down r l`, and `x y` on a Super Nintendo; a button the console lacks is a friendly build error. A computer's window has no keys for `x` and `y` yet.
- `rumble frames: 12, pattern: "##..##.."` — **shake the player's hands**, as a ball hitting a bumper does. The motor runs for `frames:` frames (0 to 65535), on or off on each by the pattern: eight frames, `"#"` on and `"."` off, read from the left and round again after the eighth. Steady by default; `"#.#.#.#."` is a light buzz. A number 0–255 is read as the Color's own games read theirs — turned a bit to the right each frame and the lowest bit read, so its frames come from bit 1 up to bit 7 and then bit 0 — and a pattern taken from one of them (Pokémon Pinball's `wRumblePattern`) plays the same (`IR::Rumble`). A rumble said while one runs takes its place, and `frames: 0` stops it. It starts on the frame after the pass that says it, and moves on with every frame shown, a slow pass's too (Pokémon Pinball counts its rumble down a pass at a time instead, which is the same while the game keeps up). A game that halts stops the motor. **Where it is felt**: on a console whose cartridge carries a motor — the Game Boy Color's, whose cartridge then says so in its header. On any other it does nothing, and the game plays the same (see each console's page). A Color cartridge with a `clock` has no motor, so a Color game that uses both is refused. **In a test**: `motor_on?` on the interpreter, a checked run and the emulator's reader says whether the motor runs on the frame shown; the checked run compares it on every pass. **What it costs**: on the Color, a few bytes of work memory, a short routine each frame shown, and two writes where it is said; a game that never says it builds the same bytes. Worked example: `test/all/vblank/builder/test_rumble.rb`, `test/lowering/gbc/vblank/ir/backends/gbc/test_gbc_rumble.rb`.
