# DSL reference: Playing a finished game with nobody at the controls

The map of every page is `.claude/rules/dsl-reference.md`. **On this page** has a line for each
verb here; the entries after it tell each one in full.

## On this page

- `VBlank.playthrough "name" do … end` — scripted presses on a cartridge; `vblank compare`.
- `assert_heard_alike ours, original, tape, ...` — two cartridges' heard sound held alike; `game.last_frame_sound`.
- `vblank run game.rb --script s.rb` / `--tape t.tape` — the one command that plays a game: a person without either, nobody with one; as Ruby unless `--on js|native|logic|interpreter`. No cartridge: `--write-mgba-script`, `--write-bk2` reach a console.
- `VBlank.bot` + `vblank bot FILE` — a script plays in a match.

## In full

Not verbs either — these drive a built cartridge.

- `walk = VBlank.playthrough "walk to the signpost" do … end` → a **playthrough**: a game driven with nobody at the controls, from a **script** that says what to press. A game can otherwise only be played by a person, or poked by a test that writes out which button is down on which frame; a script says it the way a person would, and gives the same minutes of play every time. The block is read where the playthrough is declared, so a slip in it (a button the console does not have, a count of frames that is not a whole number above nought, two moments of one name) is a friendly error there and not part way through playing. Nothing is played until `play`. The block is run with the script as itself, so the steps need nothing written in front of them; a local variable from around the block is still in reach inside it, and a method or instance variable of the place it was written is not. (And a local called `hold` or `press` would hide the step of that name.) Inside the block:
  - `press :a` — **a tap**: the button goes down for one frame and comes up for one. The frame up is part of the tap, which is what makes two taps in a row two presses — a menu reads the press and not the hold, so a button simply left down would be one press however long it stayed there. `press :l, :r` taps several together. **A tap is never missed by a slow game**: the console notes a press on every frame and hands it to the game the next time the game looks. What a slow game can do is fold two taps of one button into one, when both land inside a single trip round its loop.
  - `hold :right, frames: 40` — keep one or more buttons down for that many frames, then let go. **Frames, not trips round the game's loop**: a game that fits its work into a frame sees the button forty times, so a character that walks two pixels a time has walked eighty; a game too slow for that goes round less often and sees it fewer.
  - `wait frames: 30` — let that many frames go by with nothing pressed, for an animation to finish or a screen to settle.
  - `wait_until("the file menu is up") { |game| game.var(:screen) == 1 }` — **let frames go by until something is true of the game.** Counting frames is exact and brittle: the day a screen takes a frame longer to come up, every step after it is a frame out. This asks the game instead. The block is handed the running cartridge — the same reader `play` hands out at a moment — and is asked after every frame, so the script carries on from the **first** frame the answer is yes. It always plays one frame at least, since the game is asked after a frame and never before one. The words say what is being waited for, written to sit in the middle of a sentence, and they are not decoration: they are what a wait that never ends has to say for itself. **The block has to answer true or false.** A number is a friendly error, because Ruby takes every number for yes, nought included — so `game.var(:flags) & 4`, the way the test is written in C, would end the wait on its first frame whatever the flags were. Compare it: `(game.var(:flags) & 4) != 0`. **The reader reads lists and pools by name too**, as the interpreter does: `game.list(:floor_seconds)` is everything in a list now, oldest first, and `game.pool(:guard, :x)` is one field of a pool, an entry for each slot and nil for a free one, so `wait_until("every guard has gone") { |game| game.pool(:guard, :x).compact.empty? }`. A fraction comes back as the interpreter gives it. `game.game_state` is all of it at once. A name the game does not have is a friendly error listing the ones it has, and a cartridge that is only its file has no names to ask.
  - `hold_until("the hero is at the door", :right) { |game| game.var(:px) >= 200 }` — the same, with buttons down while it waits. They come up when the wait ends. The words come first, as in `wait_until`, and the buttons after.
  - `steer("reach the lift", within: 20_000) { |game| next :done if game.var(:floor) == 2; buttons_for(game) }` — **choose each frame's buttons from what the game is doing.** `wait_until` and `hold_until` only decide when a step ends, so a script cannot answer something it did not foresee, and a game whose enemies, ball or opponent move for themselves cannot be played to the end that way. Here the block is handed the running cartridge before each frame and answers the buttons to hold for that one frame, `[:up, :b]` or `[]` for none, or `:done` to end the step. The framework runs the loop and nothing else, so what decides the buttons is the game's own code. A frame is a picture shown, not a trip round the game's loop. **Every frame goes on the tape**, so a tape of a steering script plays back with no block and no reader, and a moment after the step falls where it did. `within:` is how many frames it can take, 600 unless it says, and past that it gives up like any wait, with its words and a picture. A step that says `:done` before any frame of the script has been played plays one, so a moment after it has a frame to name. **A count kept beside the block starts again on every playing** (`walked = 0; steer("walk") { walked += 1; ... }`): each playing reads the playthrough's block again, so a playthrough played twice, or a lead-in a comparison plays twice (once to learn the presses, once beside the other cartridge), plays the same each time. What the block reaches outside the playthrough's own block is its own to start again. Friendly errors: no words, no block, a button the console does not have, and an answer that is neither a list of buttons nor `:done`. It works on every console a playthrough plays on. Worked example: `test_playthrough_steering.rb`.
  - **A wait that never ends stops the playthrough** instead of hanging it. Both steps take `within:`, how many frames to go on asking (600, ten seconds of play, unless said). After that many the playthrough raises `VBlank::Playthroughs::GaveUp`, whose message says whose script it was, which wait in its own words, the frame it gave up on, and — on a line of its own, to copy — where it wrote a picture of the screen at that frame. The picture is usually the whole answer, because the game is on a screen the script did not expect. The error also answers `words`, `frame` and `picture`. The picture is left in a folder of its own in the machine's temporary files, and nothing takes it away.
  - **A script with a watching step is declared where it is used, not kept in a constant of a test class.** This suite runs each test on a core of its own, and a constant has to be something every core can read; a block that watches a game is not. A script that only counts frames can be a constant.
  - `moment :at_the_signpost` — **name the frame that has just been played**, so it can be asked for afterwards. A moment has to come after a step, since before the first one no frame has been played. The name is a symbol of letters, digits and underscores: a tape writes it down as a word, so it has to be one.
- **Open a script with a wait.** A cartridge spends its first frame or more setting itself up, and a press made then is deliberately forgotten — on a real console too — so that a button held through power-on is not taken as a press. A tap on the very first frame is not seen. How long setting up takes depends on the game, so a `wait_until` that watches for the first screen is the opening that survives the game changing; `wait frames: 10` is the one that needs no thought.
- `played = walk.play(cartridge) { |moment, game| … }` — play it, from power-on (or from a save, or after a lead-in: see the entries below), on a cartridge the build made (`VBlank.build`, `game.build_rom`), or on a cartridge file by its path (see below). At each named moment the block is handed the moment's name and the running cartridge, which answers everything a test of a running cartridge asks: `game.var(:px)`, `game.sprites(:hero)`, `game.pixel_gba(x, y)`, `game.frame_gba`. **What it is asked of the whole screen is cheap enough to ask on every frame**, because the emulator answers it in one pass over the picture: `game.only_color` (the one colour every pixel is, or nil), `game.brightness` (every pixel's red, green and blue added up, each 0 to 31), `game.frame_colors` (the screen as one string, two bytes a pixel, to keep a still as or to hash), `game.same_picture_as?(other)` and `game.difference_from(other)` (how many pixels differ, the box they lie in and the first of them with both colours), where `other` is another running cartridge or a `game.picture` kept from earlier. Each is answered at the precision a console shows, five bits each of red, green and blue (see `compare` below for why that is not the emulator's own bytes); `game.all_black?` is the one that asks the emulator's eight, as it always did, so a screen the display has darkened to almost nothing is black to `only_color` a frame before it is to `all_black?`. `game.frame_gba` is the same colours as a list of numbers, for looking pixels up in; it costs several frames' worth of time, so a script that only keeps or compares screens wants the others. `played.frames` is how many frames went by, `played.moments` the frame each moment fell on (`{ at_the_signpost: 42 }`), `played.game` the cartridge as the last frame left it, and `played.tape` the presses that were made (see the next entry). **`played.pictures` is the screen at each named moment** (`played.pictures[:at_the_signpost]`): every pixel's colour as the console's own 15-bit number, a row at a time from the top, so the pixel at (x, y) is at `y * 240 + x` — the same list `game.frame_gba` gives, and the one `VBlank::Graphics::PNG.write` takes. **To look at them, ask for files:** `walk.play(cartridge, pictures_in: "pictures")` writes each as a PNG named for its moment (`pictures/at_the_signpost.png`), making the folder if it is not there, and `played.picture_files` says where each went. With no `pictures_in:` no file is written and `picture_files` is empty. Each is written as its moment is reached and not at the end, so a playthrough that gives up further on leaves the pictures of how far it got. **A file already there under a moment's name is written over, and files an earlier playing left are not taken away**, so a folder used twice can hold pictures of both: give a playing an empty folder to tell them apart. Everything that can be wrong with the folder is a friendly error before a frame is played, since the first picture may be minutes of play in: a `pictures_in:` that is a file or is not a path, a folder that cannot be made or written to, and two moments whose names differ only in their capitals (`:Door` and `:door`), which are one file on a disk that does not tell a capital from a small letter. What the pictures cost is memory: each is kept for as long as what the playing handed back is, about a third of a megabyte a moment, whether or not it was written to a file. Worked example: `test/lowering/gba/vblank/playthroughs/test_playthrough_pictures.rb`. **A long playing does not pile its sound up in memory**: the running cartridge holds a minute of play at most, and the sound before that is written to a scratch file in the machine's temporary files, which is removed when the playing is no longer held or when the program ends. `game.audio_energy`, `game.sound?` and `game.audio_energy_by_frame` still answer for the whole playing, and they can be asked on every frame of it: how loud each frame was is worked out once and kept, so the only sound an asking reads is the frames played since the last one, and `game.audio_energy_by_frame.last` after a frame is how loud that frame was. The first asking of a long playing reads the file, once. (`game.audio_samples` is every sample of the playing at once, read from the file each time it is asked, so that one is slow to ask often and does hold a long playing's sound in memory.) **Frames are counted from 1**: frame 1 is the first one played. It plays in the emulator, as fast as the machine goes, and with no emulator installed it stops with what to install. Worked example: `test/lowering/gba/vblank/playthroughs/test_playthrough.rb`, which takes `examples/hero.rb` from its file screen out into the world.
- `walk.play("game.gba")` — **play a cartridge file**, wherever a cartridge goes: `play`, `tape.play` and both sides of `compare` take the path of one in place of a cartridge the build made. That is how a cartridge this framework did not build is driven — the original of a game being rebuilt, to lay the rebuilt one beside — and one of this framework's own, once it has been written to a file, is the same case. **Nothing in such a cartridge has a name.** Which variable is where and which sprite is which is what the build worked out, and that is kept beside a cartridge and never in it, so a file has none of it. **What can be read is what is really there**: the screen (`game.pixel_gba(x, y)`, `game.white?(x, y)` and the other colour tests, `game.frame_gba`), memory by its address (`game.mem8`, `game.mem16`, `game.mem32`), the sound, the save memory. **What cannot is anything by name**: `game.var(:px)` and `game.sprites(:hero)` are a friendly error saying the cartridge was not built here and what to read instead. So a script watches such a cartridge by a pixel or by an address — `wait_until("the title is up") { |game| game.pixel_gba(120, 40) == LOGO_RED }`, `hold_until("the door", :right) { |game| game.mem8(0x0300_1234) == 3 }` — where the address is one somebody found, since nothing here can say what it holds. Pictures at moments, tapes, saves and comparisons all work as on any cartridge. The framework never learns what the cartridge is: it runs the bytes it is given and keeps none of them, and all a tape says of it is the title in its heading and a checksum, for a person. **Nothing is written beside the file**: the console plays a copy of its own, and a save goes where every playthrough's does (see the next entry), so playing a cartridge twice plays the same cartridge twice. **Its save can be of any size.** Save memory comes in more kinds than this framework builds with; a save of a size its own cartridges have comes back as the same `IR::SaveImage` theirs does, and one of any other size is kept as its bytes (a `VBlank::Diagnostics::SaveBytes`), which is all that is known of it. Both answer `to_sav` and `write_sav`, and both start another playthrough. Nothing checks that a save handed to such a cartridge is one of its own, since nothing says how much save memory it has. Friendly errors before anything is played, on either side of a comparison: a path with no file at it, a file that is not a cartridge (every cartridge carries the same byte at one place in its heading, and a file without it is something else), the bytes of a cartridge given where its path was meant, and something that is neither a cartridge nor a path. Worked example: `test/lowering/gba/vblank/playthroughs/test_playthrough_cartridge_file.rb`.
- `walk.play(game.build_rom(console: :gbc))` — **play a Game Boy Color cartridge**, built here or from a `.gbc` file: the same script, the same frames and buttons, the same moments, tapes, saves and pictures (the Color's whole 160×144 screen). The running cartridge handed to each moment answers what holds on both consoles the same way: the screen and every question about it, `game.var`, memory by address, the save memory, the sound, `game.step`, and `game.showing` / `game.hearing` with the Color's own layers and voices (`game.layers` is `[:bg, :bgwin, :sprites]`). Three are answered the Color's way: **`game.sprites(:hero)`** is each sprite the game placed in its last pass, by its name, where the game put it and the picture it shows (the rows the interpreter gives, `name`, `x`, `y`, `picture` — the Color's own table of 8×8 pieces cannot say whose a piece is); **`game.palette`** is the Color's 64 colours, eight lists of four for the backgrounds and then eight for the sprites (`game.palette(:sprites, 2)` is one list of four); and **`game.passes`** is how many times round the game loop it got, counted by the Color's runtime itself, so it needs no `count_passes:` — for a `game_loop` that waits for the screen itself, once at its top, which is every game loop not told `frame_sync: :manual`; a game that also waits in places of its own is a friendly error, since the Color counts waits and not passes. What only an Advance cartridge's reader can say — `registers`, `run_until`, `wave_rate`, `pad_reads` (the Color reads its buttons a row at a time, so the emulator's count of reads is not the times the game asked), and the mixer of recordings a Color game cannot have (`voices`, `sounding`, `sample_clock`, `sound_drops`) — a Color cartridge's reader does not have at all (`game.respond_to?(:registers)` is false), and asking it anyway is a friendly error naming the Color and what to read instead. The Color's speaker settles over its first few frames after power-on, so a silent game has some sound energy there; ask about the game's own sound once it has started. `compare` lines two Color cartridges up on the Color's screen, and refuses a Color cartridge beside an Advance one, whose screen is another size. Worked example: `test/lowering/gba/vblank/playthroughs/test_playthrough_color.rb`.
- `walk.play(cartridge, save: saved)` and `played.save` — **start a playthrough holding a save, and get the save memory back when it ends.** A game that keeps its progress in the cartridge can only be played from its first screen otherwise, and the third room is then every playthrough's first three rooms over again. `played.save` is the cartridge's save memory as the last frame left it (a `VBlank::IR::SaveImage`, the same one the interpreter takes, or nil for a cartridge with no save memory), and `save:` takes one — so one playthrough plays to the save point and every other one starts there: `at_the_door = to_the_door.play(cartridge).save`, then `fight.play(cartridge, save: at_the_door)`. **Or a save file**: `played.save.write_sav("door.sav")` writes it as the file an emulator keeps a cartridge's save in, and `save:` takes the path of one (`save: "door.sav"`), from this framework or from an emulator a person played in. A save file is as big as its cartridge's save memory, which for a cartridge this framework built is 8K, 32K, 64K or 128K. **The save handed over is left as it was.** The game goes on to save over its own copy, and that is in the `played.save` that comes back, so one save can start as many playthroughs as wanted and each begins in the same place. **A game that saves needs time to**: this framework writes a save in the background, a piece each trip round the game's loop, so a script waits after the press that saves before it ends (see `save_data` for how long a save takes: a handful of trips for a kilobyte on the 32K memory, several times that on flash) — a playthrough that ends sooner hands back the save from before. **No save file is left beside the cartridge**, which is where an emulator left to itself writes one — and the next playing would then start in the last one's save. Each console keeps its save memory in a file of its own, in a folder the framework takes away when the program ends, so two playthroughs at the same moment never see each other's, and the save to keep is the one handed back. Friendly errors, before the console is switched on: a `save:` that is neither, a path with no file at it, the bytes of a save given where its path was meant, a file that is not the size of any save memory (a tape given in its place), and a save from a cartridge with another size of save memory than this one's. **A tape says which it was recorded from** — its third line is `starts from: power-on`, or `starts from: a save 0x1A2B3C4D` with a checksum of the save's bytes, for a person to tell which save the tape goes with (nothing holds the tape to that checksum, as nothing holds it to the cartridge's). One recorded from a save is refused without a `save:`, since the same presses from power-on are a different game; a tape recorded from power-on can be played from a save, and that is the caller's to mean. The save itself is not in the tape: a tape is the presses, and played on another cartridge it wants that cartridge's own save. A comparison starts both cartridges from power-on unless it is given a save for both (`save:` on `compare`, below), so a tape recorded from a save is compared with one. Worked example: `test/lowering/gba/vblank/playthroughs/test_playthrough_saves.rb`, which saves a walk in `examples/hero.rb` and starts again from it.
- `walk.play(cartridge, lead_in: past_the_logos)` — **a lead-in: another playthrough, played on the cartridge first and not counted.** A cartridge somebody else made shows its logos and an introduction before its first screen and another does not, so the same script from power-on finds the two in different places before a button is pressed. A lead-in gets a cartridge to where the playthrough should begin by its own road, which is usually a wait that watches for the first screen: `past_the_logos = VBlank.playthrough("past the logos") { wait_until("the title is up") { |game| game.pixel_gba(120, 40) == LOGO_RED } }`. **Nothing in it is counted**: frame 1 is the first frame after it, `played.frames` and `played.moments` count from there, and its presses are not on the tape. A moment it names is nobody's to ask for. It is played after the console is switched on holding its `save:`, so the two go together. **A tape says it was recorded after one** — its third line ends ` after a lead-in` (`starts from: power-on after a lead-in`) — and is refused without a `lead_in:`, since with none the same presses start in a different place. The lead-in itself is not on the tape, for the reason a save is not: it is how THIS cartridge gets to the start, and another cartridge has its own. A wait in a lead-in that never ends gives up as any wait does, saying it was the lead-in's. Something that is not a playthrough is a friendly error. Worked example: `test/lowering/gba/vblank/playthroughs/test_playthrough_lead_in.rb`.
- `tape = played.tape` → a **tape**: the presses of that playing, written down — which buttons were down on each frame, and the frame each named moment fell on. **A script says what to do; a tape says what was done.** The difference shows the moment a script watches the game: `hold_until("the door", :right)` is as many frames as *this* game took to reach the door, and the tape holds that number, so it needs nothing to watch. That makes a tape the same presses on the same frames whatever it is played on, which is what lets two cartridges be handed exactly the same game. `tape.play(cartridge) { |moment, game| … }` plays it, and gives back what playing a script gives back, pictures included (and `pictures_in:` writes them the same way). `tape.frames` and `tape.moments` read it without playing it. `tape.up_to(46)` is the same tape ending on that frame: a hold the frame falls inside is cut short, a moment is kept when the frame it names is still on the tape, and a frame past the end is the whole tape — play it and the cartridge is on that frame. `tape.presses_within(1..60)` says what was down on those frames, as a list of stretches each with its `frames` (a range) and its `buttons`. `tape.write("walk.tape")` writes it to a file and `VBlank::Playthroughs::Tape.read("walk.tape")` reads one back, the same tape. **The file is plain text**, a line for each stretch of frames with the same buttons down, so a person can read one, write one by hand, and see a change to one as a change to a few lines:

  ```
  vblank tape 1
  recorded on: HERO 0x5C0FFEE5
  starts from: power-on

  10 -
  1 down
  1 -
  20 right up
  moment walked
  ```

  Three lines of heading, always those three in that order. Below them: a count, then the buttons down for that many frames, `-` for none; a moment on a line of its own, naming the frame the line before it ended on; and, for the reader, blank lines and lines that start with `#`. A hold of twenty frames is one line, and two lines that say the same buttons are read as one. **What it was recorded on is for a person**: the cartridge's title and a checksum of its bytes say which game and which build the tape came from, and nothing holds the tape to them — playing it on another cartridge is the point. (A title holding bytes that cannot be printed, as a cartridge somebody else made can, is written with `?` in their place.) A line that cannot be read is a friendly error naming the line, what is on it, and what a line there has to look like; a file that is not there, or is not a tape, is one too. **A tape can be kept in a constant** and read from any core, which a script with a watching step cannot: it holds nothing but names and numbers. Worked example: `test/lowering/gba/vblank/playthroughs/test_playthrough_tape.rb`.
- `result = walk.compare(ours, theirs)` (also `tape.compare(ours, theirs)`) → a **comparison**: two cartridges played side by side on the same presses, and the first frame on which their pictures differ. Somebody rebuilding an existing game wants to know where their cartridge has drifted from the original, and a change to a game that moves something a frame early wants catching without two people looking at two screens; both are the same question. `result.drift?` says whether the two ever differed, `result.drift.frame` the first frame they did, counted from 1, and `result.drift.moment` the last moment the script named before that frame, for a person to place it by — nil when it had named none, and a moment naming the very frame they drifted on is not before it. `result.drift.differed` is what differed on that frame: `[:picture]`, unless readings are compared too (see `readings:` below). `result.drift` is nil when they never did. `result.frames` is how many frames were played. **There are two ways to compare, and this is the one a comparison uses with nothing said** (the other, `same: :script` below, plays the script on each cartridge by itself and compares the two at each named moment, which forgives timing). **Both get the same presses on the same frames.** What is compared is a tape, so a script is first played on the FIRST cartridge alone, to make one — and where that script watches the game (`hold_until("the door", :right)`), it is the first cartridge it watched, and the second is handed exactly the walk the first one took. A second cartridge whose door is a frame further off is still walking when the first has stopped, and the two differ from there. A tape holds its presses already, so it is compared as it stands. **Every pixel of every frame, and it stops at the first drift**: one frame out is nearly always every frame after it out too, so the first is the one worth having, and `result.frames` is then how far it had played when it stopped. (`carrying_on: true`, below, plays to the end and lists every drift.) **The same colours are the same picture**, whatever the console built them from: a rebuilt game that draws with a sprite what the original drew with a background has not drifted, so long as every pixel comes out the colour the original's does. **A colour is compared at the precision a console shows**, five bits each of red, green and blue. The emulator keeps eight, and what it holds below the five is its own working: it fills a colour read out of the colour table in one way, and works a colour the display brightened, darkened or mixed out at all eight. So it can hold the same five-bit colour as two different numbers, and two screens that differ only down there are one picture here: a game that fades where the original swapped colours has not drifted, so long as its colours come out the same at five bits. What it costs is the two cartridges running at once and a compare of the two pictures a frame, which comes to about half the speed of playing one; a script costs one more playing of the first cartridge before that, which a tape does not. Worked example: `test/lowering/gba/vblank/playthroughs/test_comparison.rb`, which builds `examples/hero.rb` a second time with a quicker hero and finds the frame the two part on. **How alike is alike enough is said where the comparison is made**, on `compare`, with the settings below. With none of them said, one pixel out on one frame is drift — right for checking that a change to a game moved nothing, and wrong for a game being rebuilt to match another, where one stray pixel several minutes in would hide everything after it. Each is read before a frame is played, so one that makes no sense — or a setting `compare` does not have, which is a name spelled wrong — is a friendly error straight away:
  - `share_may_differ: 0.01` — **the share of the pixels that may be a different colour** before a frame counts as differing, from 0 to 1: a share and never a count, so `1` is every pixel there is. The screen has 38,400 pixels, so 0.01 is 384 of them and `1.0 / 38_400` is one. A frame differs when MORE than that share is out; exactly that many is still alike, however the share was written. **It is a share of the pixels that are looked at**: with half the screen ignored (below), 0.01 is 192 pixels, so ignoring more of the screen never makes the share looser than it says.
  - `frames_in_a_row: 3` — **how many frames running have to differ** before it is drift, 1 unless said, so that one frame of flicker is not. (Where readings are compared too, each thing counts its own: see `readings:` below.) The frame reported is the FIRST of the stretch and the moment the one before that frame, while `result.frames`, for a comparison that stops at its first drift, is the last frame it had to see to be sure. A stretch that ends sooner is forgotten, and so is one the tape runs out on.
  - `ignoring_rectangles: [[0, 128, 240, 32]]` — **rectangles of the screen that are not looked at**, each `[x, y, width, height]` in pixels from the top left: a status bar not drawn yet, a clock, a part known to differ. A difference wholly inside them is no difference; one that reaches outside still counts by the pixels outside. Rectangles can overlap. A rectangle has to lie on the screen, and one written with no list around it (`ignoring_rectangles: [0, 128, 240, 32]`) is a friendly error showing how one is written.
  - `looking_at: [[0, 0, 240, 128]]` — **only these parts of the screen are looked at**, the rest left out; `ignoring_rectangles:` then leaves parts out inside them. A share is of what is left. A rectangle off the screen is refused, as for `ignoring_rectangles:`.
  - **A part for each stretch of frames, or a part worked out on every frame.** `looking_at:` and `ignoring_rectangles:` each take one of three things. A list of rectangles is the same part on every frame. **A hash of stretches** gives each stretch its own rectangles, a stretch being a range of frame numbers or of moments as in `ignoring_frames:` below: `ignoring_rectangles: { (..:in_the_world) => [[0, 0, 240, 16]], (:in_the_world..) => [[0, 128, 240, 32]] }`, for a rebuilt game whose title bar comes before its status bar. A frame several stretches cover takes all their rectangles, and one that no stretch covers is looked at whole. **A block**, `->(first, second) { [[x, y, w, h], ...] }`, is handed the two running cartridges (and the frame's number, counted from 1, when it takes three: `->(first, second, frame)`) and answers the rectangles for that frame: a part that belongs to the scenery and slides when the view scrolls (read the scroll from the game, by a variable on a cartridge built here and by an address on a cartridge file, and take it off the part's place in the world), or a box round something the game draws differently from the original. It is asked on every frame in order, the frames `ignoring_frames:` leaves out included, so it can keep what it saw on the frame before (a console draws a frame from where the view was as the frame before it ended) and that is never stale after a stretch left out; with the two lined up step by step (`by_passes:`, `skipping_still_frames_of:`) it is asked once a step. A rectangle a block answers is cut to the screen and never refused, since a part that moves slides off the edge; an answer that is not a list of four whole numbers each is a friendly error naming the setting. What it costs is the block, once a frame, and a part worked out again only when the rectangles change. Both of these are refused on the same script (no frame the two share) and by `write_side_by_side_picture` (one frame, one part).
  - `pixels_apart: 2` — **look at every second pixel across and down only**, counted from the top left corner: a quarter of the screen, and still every 8-pixel tile in it. For a port that has only part of its tiles right yet, a pixel off the grid is never looked at; a share is of the pixels on it. 1 unless said, and not a whole number above nought is a friendly error.
  - `layers: :backgrounds` — **the picture without its sprites**, or `layers: :sprites` for **the sprites alone**, on both cartridges for the whole comparison (the console draws without the rest: see `game.showing`). For a rebuilt game whose scenery is right and whose characters are not yet, or the other way round. **The sprites alone are what the sprites draw**: a cartridge shown no background shows the backdrop wherever no sprite draws, a colour each cartridge can keep its own way under a room that hides it, so the colour most of that picture is reads black on both (`game.leave_out_backdrop!`), and only what the sprites draw is compared, in the picture a report keeps too. A sprite pixel of the backdrop's colour reads black with it. The Advance and the Color can; a Super Nintendo or Genesis cartridge cannot (the emulator draws every layer together) and is a friendly error naming the cartridge. Refused on the same script. **A layer for each**: `layers: [%i[bg0 bg1], %i[bg1 bg2]]`, the first cartridge's and then the second's, for a port that draws its room on other layers than the original; each is a list of the layers to keep in `game.showing`'s names, `{ only: [...] }` or `{ without: [...] }`, one of the two words, or `nil` for the whole picture. A list that is not two, or an entry that is none of those, is a friendly error, and a layer a cartridge's console does not have is refused naming that cartridge. Anything else is a friendly error.
  - `ignoring_sprites: true` — **leave out the box of every sprite either cartridge shows**: on each frame looked at, every entry of each console's own sprite table on that frame and on the frame before it, on both cartridges, is a rectangle not looked at on both pictures. For a port whose scenery is right and whose characters are not made yet: the original shows its characters on top of the scenery anyway, so the port is held to the original's scenery everywhere but under them. Unlike `layers: :backgrounds`, which draws both pictures without their sprites and so holds the port to the scenery UNDER every character as well, this leaves those pixels out; and it works on every console a comparison lines up, the Super Nintendo and the Genesis included, whose emulators cannot draw a picture without its sprites. **The frame before too**, because a console draws a frame from a table the game wrote a frame or so earlier; lined up step by step (`by_passes:`, `skipping_still_frames_of:`), the frame before is each cartridge's own, the frame it played before the one it showed the step on. **The table is read raw**, as the console holds it (`game.sprite_boxes`), so a cartridge of the original with no build record is read the same as ours: the Advance's 128 entries by shape and size, the Color's forty pieces (8 wide, 8 or 16 tall as LCDC sets), the Genesis's table followed by its links. **A Super Nintendo cartridge's sprites come in two sizes the game sets** in a register the emulator does not hand over, so for one the setting is those two sizes, small then large: `ignoring_sprites: [[8, 8], [16, 16]]` (what VBlank's own build sets); `true` there is a friendly error saying so. It goes with every other setting: `ignoring_frames:` for the frames before the scenery is ready, `ignoring_rectangles:`, a share. A report says the sprites were left out. Refused on the same script (no frame before at a moment), and beside `forgiving_torn_frames_of:`, whose rule does not take each frame's own boxes yet. Anything but `true`, `false` or two sizes is a friendly error. On the Advance a turned sprite drawn at double size is left out at its picture's size only, the box its table names. `vblank compare` takes it as `--ignoring-sprites`, and the Super Nintendo's sizes as `--sprite-sizes 8x8,16x16`. What it costs is each table read after every frame either cartridge plays. Worked examples: `test/lowering/gba/vblank/playthroughs/test_comparison_ignoring_sprites.rb`, and the Color's and the Genesis's beside their own lowerings' tests.
  - `forgiving_torn_frames_of: :second` — **the strict rule for a frame shown torn.** An original game that changes the picture while the console is drawing it shows that frame part old and part new, and the frame after it whole; a port that changes it at the right moment never shows the torn frame, so the two differ on that one frame though the port is right. `frames_in_a_row: 2` forgives that, and forgives a port that is a frame late just as readily. This forgives exactly one thing: on a frame where the named cartridge's picture is unlike both the frame before it and the frame after it, the other cartridge must show the frame after it (by the other settings: parts, share), and then the picture is not counted as differing on that frame. Anything else is a difference as before, readings included. It is `:first` or `:second`, the cartridge whose torn frames are forgiven, and anything else is a friendly error. What it costs is a frame of waiting: each frame is decided once the frame after it has been played, and the last frame of the tape is taken as it was seen. Refused on the same script. Worked example: `test/lowering/gba/vblank/playthroughs/test_comparison_torn_frames.rb`.
  - **Which video memories differ.** Where the picture is what differed, `result.drift.video_differences` lists the console's video memories that differed between the two on the frame it began, each with its first difference (`memory`, `at`, `first`, `second`): `:colors` (the colour table, by colour number), `:sprite_table` (by byte), `:scroll` (each background's across and down; the Color's SCX, SCY, WX, WY) and `:registers` (the video registers that can be read back, by name). Two pictures that differ say where; this says which part of the console made them differ — the colours for a palette fault, the sprite table for a sprite in the wrong place, none of them for the pictures of the tiles. The Super Nintendo's are the colours and the sprite table only. The Genesis's scroll is its vertical scroll memory by word, and its registers the video chip's 24 by number. Empty for a drift of readings alone and at a moment. A report and `assert_plays_alike` say them. Worked examples: `test_comparison_layers_and_memories.rb`, `test_comparison_screen_parts.rb`.
  - `ignoring_frames: [1..120, :title..:in_the_world]` — **stretches of the playthrough that are not looked at**: an opening the rebuilt game does not have yet, a screen that shows the time of day. Both cartridges are still played through a stretch, since the game has to get to the other side; what differs inside it is not counted, and the comparison carries on to the next drift outside it. A difference that begins inside a stretch and is still there when it ends is drift on the first frame after. **A stretch is a Ruby range, of frame numbers or of the names of two moments.** The named form is the one to reach for, because frame numbers all move the day a script gains a step and the moments move with the game. A moment stands for the frame it names, so `:title..:in_the_world` is those two frames and every frame between, the same on a script and on its tape. Both frames, because of how a moment usually comes to be: a script waits until the title is up and names that frame, which is the first frame OF the title, and leaving it in would report the title as drift on the one frame of it that was not left out. Being a range it means what one means: three dots leave its last frame out, `(900..)` runs to the end of the playthrough and `(..:title)` from its start. A range with neither end is every frame, and is refused: a comparison that looks at no frame finds nothing. A frame that is not looked at also breaks a run of differing frames, so with `frames_in_a_row:` the frames either side of a stretch are never frames in a row. Friendly errors, all before a frame is played: a moment the playthrough does not declare (naming the ones it does — a script says its moments where it is declared, so this costs no playing), two moments or two frames the wrong way round (shown the right way round), a range that goes below frame 1, a range that holds no frame, and one range written with no list around it. One is found later, because it is not known sooner: two moments a script declares one straight after the other name the same frame, and three dots between those leave out the only frame there is — refused once the script has been played and the frames are known, and on a tape before anything is played.
  - `readings: { paces: :paces, hero_x: [:px, ->(game) { game.mem16(0x0300_1234) }] }` — **named readings: numbers read off both running cartridges on every frame that is looked at and compared, as well as the picture.** Two games can show the same screen and be a long way apart underneath — a position a pixel out behind a wall, a counter that will run out a second early — and where the pictures do differ, "the hero is at 61 on one and 60 on the other" says what went wrong where two screenshots only say that something did. A reading is a name you choose and a way to read it, and there are four ways to say the way. **A variable's name** (`paces: :paces`) reads that variable from both, which is all it takes on two cartridges this framework built. **A block** (`where: ->(game) { [game.var(:x), game.var(:y)] }`) is handed each running cartridge in turn — the same reader a script's `wait_until` is handed — and what it gives back can be anything two of which can be the same: a number, a pair of them, a colour's name. **A list of two** (`hero_x: [:px, ->(game) { game.mem16(0x0300_1234) }]`) is one way for each cartridge, the first's and then the second's, each a variable's name or a block. That last one is what somebody rebuilding a game needs, because the two cartridges are not the same program: the rebuilt one keeps the hero's position in a variable with a name and the original keeps it at an address somebody found, and it is "the hero's position" all the same. **A sprite or background named** (`hero: { sprite: :hero }`, `sky: { background: :sky }`) is read whole, its place, whether it is shown and its picture (a background's scroll and map), and is refused before a frame is played on a cartridge that has none of that name; one part of one is a block, `->(game) { game.sprite(:hero).x }`, and the music's loudness is `->(game) { game.music_volume }`. **A reading that differs is drift on the first frame it differs**, like the picture: `ignoring_frames:` leaves it out of the same frames, and `share_may_differ:` and `ignoring_rectangles:` are about the picture only — a reading is the same on both or it is not. (Two values that are both not a number count as the same.) **With `frames_in_a_row:` each thing counts its own frames**: the picture has to differ that many frames running, or one reading has to. A picture that flickers for a frame and a count that is out on the next are two flickers and no drift, where counted together they would be two frames in a row. `result.drift.differed` then lists what differed from that frame for as long as it took, the picture first: `[:picture, :paces]`, or `[:paces]` for two cartridges whose screens agree. **`result.drift.readings` is every reading on both cartridges on that frame**, the ones that agree too, each name with the first cartridge's value and the second's (`{ paces: [1, 2], where: [22, 22] }`); the ones that agree say what the difference is not. With `frames_in_a_row:` they are of the frame the drift began. What it costs is each reading read once from each cartridge on every frame that is looked at, whether or not readings are compared, which for a variable or an address is one read of memory. **A block that stops with an error** raises `VBlank::Playthroughs::Comparison::ReadingFailed`, which says which reading and which cartridge (the block's own error is its `cause`); since every reading is read on the first frame that is looked at, that is where a block that cannot work is found. Friendly errors, before a frame is played: a variable's name on a cartridge that was not built here (a cartridge file has no names — give that side a block that reads memory by its address), a variable the cartridge does not have (naming the ones it does), a sprite or background the cartridge has no name for, a way that is none of the four, a name that is not a symbol, and a reading named `:picture` or `:frames_apart`, which are what the picture and the frames between the two are called where what differed is listed. Worked example: `test/lowering/gba/vblank/playthroughs/test_comparison_readings.rb`.
  - `comparing: [:readings]` — **what is compared, as a list**: `:picture`, `:readings`, or both. With nothing said it is the picture, and the readings where any were given. **The readings alone** is for a game whose numbers are right long before its pictures are: the hero walks at the right speed weeks before the scenery is drawn, and comparing the readings only says whether the game underneath has drifted while every frame of the picture still differs. **The picture alone, with readings given**, compares the picture and still reads the readings, so a drift in the picture says what each reading was on both cartridges without a reading that is known to differ being called the drift. Friendly errors: an empty list, something that is not a list, a thing a comparison cannot compare, and `:readings` with no `readings:` given.
  - `carrying_on: true` — **play on past the first drift, to the end, and list every stretch of drift.** It answers what the first drift cannot: do the two come back into step, or is everything after it different for one reason? A hero who takes a corner a frame late and is in step again a second later is a different finding from one who is a pixel out for the rest of the game, and the first drift is the same frame in both. `result.drifts` is every drift in the order they happened, and each says the frame it began on (`drift.frame`), the last frame of it (`drift.last_frame`), both as a range (`drift.stretch`, `46..48`), how it ended (`drift.ended`), and what any drift says: its moment, what differed, the readings on the frame it began. `result.drift` is still the first, and `result.frames` is then the whole tape. **How a drift ended is the answer to the question**: `:back_in_step` when the next frame was one on which the two were within the settings again (`drift.back_in_step?`), `:tape_ran_out` when the two were still apart on the last frame of the tape, and `:not_looked_at` when the next frame was one `ignoring_frames:` leaves out, where nothing is known and a difference still there afterwards is another drift. **A drift is under way while something goes on differing that has differed for as long as `frames_in_a_row:` asks**, and its last frame is the one before the frame on which nothing has. With one frame asked for, that is every differing frame until the first frame the two are alike again. With three, a reading that is out for a single frame straight after a picture's drift does not carry the drift a frame further — and a single frame alike in the middle of a long difference does end it, the rest being a drift of its own once it has lasted three frames again. **No frame is in two drifts**: where one thing stops differing while another that had already begun goes on long enough to count, that is one drift from the first frame of the one to the last of the other. **`drift.differed` is everything that differed for long enough while the drift lasted**, in the order each began, so a drift the picture began and a reading carried on says `[:picture, :late]`. **With nothing said it stops at the first drift**, `result.drifts` holds that one, and its `last_frame`, `ended` and `stretch` are nil: a comparison that stops never finds out how long the drift lasted. What it costs is the rest of the tape played, and with `reports_in:` a report written for every drift — so two cartridges that flicker differently on every other frame for a minute write nearly two thousand folders, and want `frames_in_a_row:` said first. Not `true` or `false` is a friendly error. Worked example: `test/lowering/gba/vblank/playthroughs/test_comparison_carrying_on.rb`.
  - `same: :script` — **play the same script on each cartridge by itself, in place of the same tape on both**, and compare the two at each named moment. There are two ways to compare and they find different things. **On the same tape**, which is what a comparison does with nothing said, the second cartridge is handed the first one's presses on the first one's frames: a door that opens a frame late is out of step from that frame on, and every frame after it differs. That is the strict comparison and the right one for a change that should move nothing, or for a rebuilt game that is nearly there. **On the same script** each cartridge presses A when its own text box is up and stops walking at its own door, so each arrives at "the door" however long it took, and the two are compared there. That forgives timing and finds a game that LOOKS different, which is the one to use while a rebuilt game is still frames out everywhere and the question is whether its screens are right. **The two are compared at the moments the script names and nowhere else**, since there is no frame they share: the picture and any readings, exactly as they were as each cartridge reached the moment. A drift then names the moment it is at (`drift.moment`), its `frame` is the frame the first cartridge reached it on, and it has no last frame, being one point. **`result.moments` is the frame each cartridge reached each moment on**, the first's and then the second's (`{ title: [12, 12], door: [200, 203] }`), so how long each took is always said, drift or not. (On the same tape it is there too, the same frame twice, for the moments reached before the comparison stopped.) `result.frames` is the frames the first cartridge played. It stops at the first moment that differs unless `carrying_on: true`, which lists every one. `share_may_differ:`, `ignoring_rectangles:`, `readings:` and `comparing:` mean what they mean on a tape; `ignoring_frames:` takes ranges of MOMENTS only and leaves out the moments a range covers. What it costs is each cartridge played once from start to end, whatever is found, and no comparing between moments. Friendly errors, before anything is played: a script that names no moment, or whose every moment `ignoring_frames:` leaves out (there is nowhere to compare), `frames_in_a_row:` or a range of frame numbers (each cartridge counts its own frames, so neither means anything), `same:` given anything but `:tape` or `:script`, and `same: :script` or `frames_apart:` given to a tape, which holds presses and no script. A script that gives up on one of the two — the second never reaches what the first reached — raises the playthrough's `GaveUp`, saying which cartridge, which wait and where its picture is; what the two had been through before that is not kept. Worked example: `test/lowering/gba/vblank/playthroughs/test_comparison_same_script.rb`.
  - `by_passes: [:passes, ->(game) { game.mem8(0xFFB4) }]` and `pass_count_wraps_at: 256` — **line the two up by the game's own passes, not by frames.** A pass is one run of the game's loop; most take a frame, and a pass with much to do takes two or three, the screen showing that pass all the while. An original that does this now and then is out of step with its port from the first slow pass, frame by frame, and `frames_in_a_row:` only forgives a few frames of it. Here each cartridge says its count of passes, read after every frame the way a reading is (`readings:` above): `true` for the game loop's own count, which a cartridge built here keeps (`game.passes`); a variable's name; a block handed the running cartridge, which reads an original's counter by its address; or a list of two, one for each. **The first cartridge plays the tape frame by frame; on a frame its count shows a pass for the first time, the second is played on until its own count shows that pass, and the two are compared there**, each on the first frame it showed it. The second is held, on each frame it plays, the buttons the first held on the frame it showed that pass, so a press lands on the same pass on both; a game reads its buttons once a pass, so a press held only on the later frames of the first's slow pass reaches neither. A pass one of them goes past without showing is not looked at, as a frame `ignoring_frames:` leaves out is not. `frames_in_a_row:` counts passes; frame numbers elsewhere (`ignoring_frames:`, a part for a stretch of frames, a block's third argument) are the first cartridge's. A drift says `drift.pass` and `drift.second_frame` beside `drift.frame` (the first's), `result.moments` says each cartridge's own frame, and `assert_plays_alike` says the pass. `pass_count_wraps_at:` takes each count modulo that number and counts it on past each wrap, for a counter kept in a byte (256); without it a count that goes down raises `VBlank::Playthroughs::Comparison::PassCountFell`. With it, any fall is a lap, a count the game sets back included. A second cartridge whose count stands still for a minute of frames short of a pass raises `PassNotReached`, and so do two counts that never show the same pass, which compare nothing. Friendly errors, before a frame is played: a way to count that is none of those, `pass_count_wraps_at:` without `by_passes:` or not a whole number above 1, `true` for a cartridge not built here, and `same: :script`, `forgiving_torn_frames_of:` or `reports_in:` beside it. A count that is not a whole number raises `ReadingFailed`. Worked example: `test/lowering/gba/vblank/playthroughs/test_comparison_by_passes.rb`.
  - `passes_compared_at: :end` (beside `by_passes:`; `:start` is the default) — **compare each pass at its end, not on its first frame.** An original often counts a pass at the top of its loop and then runs over the frame: on the first frame that shows a slow pass its work is half done (a ball's speed not yet turned at a wall), and a port that finishes the pass in one frame is reported as different. At the end, **each pass's readings are those of the last frame that shows it, and its picture is the frame after that one**, since a frame is drawn from the numbers of the frame before. The two are compared once each cartridge's count has gone past the pass; the second is played on until its count does, held the buttons as at the start, and a pass whose last frame it did not show (its count jumped over it) is not looked at. `drift.frame` and `drift.second_frame` are the frames of the picture, the frame after each pass's last. The last pass the tape shows has no end on it and is not compared. After `lead_ins:`, the later of the two passes the lead-ins left is compared too, since both still show its end. It goes with `pass_count_wraps_at:`, `reads_buttons_every_frame:`, `ignoring_sprites:` (the boxes of the picture's frame and the frame before), `readings:`, `comparing:` and `layers:`. What it costs is every reading read after every frame either cartridge plays, not only on the frames compared. Anything but `:start` or `:end` is a friendly error, and so is the setting without `by_passes:`. `vblank compare` takes it as `--passes-compared-at end`. A port held to its original writes: `assert_plays_alike ours, original, tape, by_passes: [:passes, ->(game) { game.mem8(PASS_COUNTER) }], pass_count_wraps_at: 256, reads_buttons_every_frame: true, lead_ins: [ours_lead, original_lead], passes_compared_at: :end, readings: { ball_x: [:ball_x, ->(game) { game.mem16(BALL_X) }] }`. Worked examples: `test/lowering/gba/vblank/playthroughs/test_comparison_by_passes.rb`, and the Color's, the Super Nintendo's and the Genesis's beside their own lowerings' tests (`test/slow_pass_games.rb`).
  - `skipping_still_frames_of: :second` (or `:first`, or `:both`) — **skip that cartridge's own still frames**, each frame whose picture is the same as the frame before's: a room loading, a fade held. An original loads each room for as long as that room takes and a port for another length, so frame by frame the two are out of step after the first load, and `ignoring_frames:`, which leaves out the same frame numbers on both, cannot help. Here a side whose still frames are skipped counts only its frames whose picture changed, the other side counts every frame, and the two are lined up by those counts the way `by_passes:` lines them up by passes: the first plays the tape, and the second is played on to each frame the first counts. A game reads its buttons on its still frames too (a title waiting for START), so the second is held the first's buttons of every frame since the frame counted before, in order, one a frame: the last again if it takes more frames, the rest never if it takes fewer. Frame 1 is never still. A frame is still in the part of the screen looked at on every frame, so with `layers: :sprites` a still frame is one whose sprites stood still, and a clock left out with `ignoring_rectangles:` does not keep a load moving. **Skip one side for a side that alone holds still** (an original's room load the port does not have); where both hold still together (a hero standing in a still room, a pause), the side not skipped counts those frames and the other does not, so the two part: skip both. A drift says `drift.second_frame` beside `drift.frame`, and `result.moments` each cartridge's own frame. A second cartridge whose picture stays the same for a minute of frames after the first's changed raises `VBlank::Playthroughs::Comparison::PictureStoodStill`. Friendly errors: anything but the three, and `by_passes:`, `same: :script`, `forgiving_torn_frames_of:` or `reports_in:` beside it. Worked example: `test/lowering/gba/vblank/playthroughs/test_comparison_still_frames.rb`.
  - `frames_apart: 5` — **how many frames apart the two may reach a moment**, on the same script. It is not checked unless said: a rebuilt game is compared for its look first, and for its timing when somebody is ready to. With it, two cartridges further apart than that at a moment drift there, `drift.differed` holding `:frames_apart`, though their screens are the same. It is a friendly error on the same tape, where the two are always on the same frame, and when it is not a whole number, 0 or more.
  - `lead_ins: [nil, past_the_logos]` and `save: "door.sav"` — **start the two cartridges in step.** Two cartridges from power-on are only in step when they are the same game built two ways. An original and a game rebuilt to match it differ before anything is pressed — logos, an introduction, a different number of frames to the first screen — and every frame after that is drift for a reason nobody is asking about. There are two answers and they can be used together. **A lead-in for each** is a playthrough of its own played on that cartridge first, the first cartridge's and then the second's, either of them `nil` for none (see `lead_in:` on `play`, above): each gets its cartridge to the same place by its own road, and the comparison starts there. Its frames are not on the tape and are not compared, and **frame 1 of the comparison is the first frame after both lead-ins**, so every frame number in the result and in a report counts from there. **One save for both** (`save:`, a save a playthrough handed back or the path of a save file, exactly as on `play`) switches both consoles on holding it, which skips whatever a game does before its save is loaded. **A save for each** (`saves: [ours, theirs]`, the first cartridge's and then the second's, either `nil` for none; `--saves FIRST SECOND` with `-` for none) is for two cartridges that keep the same moment in saves of their own shapes, a port and its original: each console is switched on holding its own. `save:` and `saves:` together are a friendly error, and so is `saves:` that is not a list of two; a save for one cartridge that is not one, or does not fit that cartridge, is refused naming which. A tape recorded from a save is compared with `save:`, or with `saves:` holding one for each. A report says where the two started, and its tape says it too, whatever the tape that was compared said, so the tape is played back with the lead-in or the save it needs. **Where the two were started differently** — a lead-in for one and none for the other — a report holds a tape for each, `first-to-the-drift.tape` and `second-to-the-drift.tape`: the same presses under two headings, each playing its own cartridge. A tape recorded after a lead-in is compared with `lead_ins:` holding at least one, and one recorded from a save with `save:`; without, it is a friendly error.
